# Plan: what to keep from the old Cloud repos

**Status:** Archive created and verified. The old folders are deleted. Port from the bundles in `archive/cloud-old/`. Lemon Squeezy is sunset, so PayMongo is the only billing path.

## What was found

None of the three repos has a plan or ADR folder, and none has a git remote. The decisions live in code, commit history and one design skill.

| Repo | Contents | Verdict |
|---|---|---|
| `cloud-v1` | 16 commits: design system, marketing pages, domain models, job engine, Lemon Squeezy and PayMongo billing, CLI licensing | Main source to port from |
| `cloud-v2` | Bare starter skeleton, no git | Nothing to keep |
| `cloud-v3` | 2 commits: the fullest PayMongo integration, with tests | Port for the billing milestone |

## Archive (`archive/cloud-old/`)

- `cloud-v1.bundle`, `cloud-v3.bundle`: full git history, verified by restoring.
- `cloud-v1-uncommitted.patch`, `cloud-v3-uncommitted.patch`, `cloud-v3-untracked.tgz`: work that was never committed.
- `larakube-cloud-design-skill.md`, `cloud-v1-design-tokens.tgz`: the brand rules and tokens.

Restore with `git clone archive/cloud-old/cloud-v1.bundle`. `.env` files are not archived, except the PayMongo keys in `paymongo-keys.env` (mode 600, never commit or print).

## Port by milestone

**First server (from `cloud-v1`)**
- `CloudOperation`, `OperationStatus`, `OperationType`, `DispatchCloudOperation`, `CloudOperationUpdated`, `CloudOperationFailed`
- `JobRunner`, `FakeJobRunner`, `KubernetesJobRunner` (remove secrets from the Job spec first), `KubernetesConnector`, `ApplyManifest`
- `OperationCallbackController` and its signed route
- `ReconcileCloudOperations`
- `CloudProvider`, `ClusterKind`, `StackStatus`, and `StackPolicy`/`ClusterPolicy` as the starting point for `Server` and its policy

**Design (from `cloud-v1`)**
- Rules to keep:
  - Product naming: LaraKube CLI, LaraKube Cloud, LaraKube Local CA, `larakube` as the command. Console is retired by Desktop, so add LaraKube Desktop.
  - The dark terminal card as the signature motif, in place of illustrations.
  - Voice: developer to developer, short sentences, sentence case, no emoji, no hype. Show a command instead of an adjective.
- Components: `TerminalCard`, `SectionEyebrow`, `StatCard`, `RoleChip`
- Decide: blue or red accent, and JetBrains Mono (v1) or Geist Mono (Desktop)

**Landing page (from `cloud-v1`)**
- Structure of `welcome`, `product`, `pricing`, `about`, `legal`, and the marketing chrome. Rewrite the copy against what is actually built.

**Billing (later)**
- `cloud-v1`: `Entitlement`, `HasEntitlements`, `Entitlements`, `config/pricing.php` (placeholder prices), hybrid subscription and 30-day pass, Lemon Squeezy
- `cloud-v3`: PayMongo connector, requests, webhook verifier and their tests. Prefer these over v1's smaller PayMongo service.

**CLI licensing (later)**
- `CliLicenseController`, the device authorization screen, CLI pricing page, license key tables

## Not porting

- `.infrastructure/` manifests: regenerated by the LaraKube CLI.
- Bundled `.claude`/`.agents` Boost skills: regenerated by Boost.
- Marketing claims that don't match the product.
